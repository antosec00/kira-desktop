# Verification and uncertain outcomes

Distinguish a plan, an issued tool call, a service-recorded effect and a confirmed
provider terminal outcome. A completed turn is not proof that every conclusion is
correct. Human research assessments remain attributed judgments; valid source
references establish provenance, not the truth of the interpretation.

For project tools, tests qualify the selected immutable revision against declared
cases and contracts. Check exit status, valid JSON/schema and expected outputs.
Retain limitations and relevant source/dependency hashes. Changing the code or
requirements requires fresh qualification. Do not call a tool universally verified
because one test passed.

Cancellation requested is not confirmed termination. If execution or cleanup is
uncertain, inspect the recorded operation and current evidence before considering
another explicit invocation. Do not automatically retry effects with unknown
outcomes. Native authentication completion likewise does not prove website login;
the site's subsequent state must establish that separately.

Use linked original sources when a summary is insufficient or contradicted.
Missing, truncated, stale or unverified evidence must remain visibly identified.
